# Product fixes after the 100-task failure analysis

The earlier run at `f7141eb` remains a baseline: 52/100 passed. These changes have **not** been scored in a new 100-task run.

| Finding                                                                               | Change                                                                                                                                                                                                                                                                               | What it guarantees                                                                                                                                                     |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A mistyped recovery ID was reported as if the workbook had no checkpoints.            | `resolveSnapshotGroup` now distinguishes an empty history from an unknown ID and tells the caller to list current IDs. Snapshots without an operation ID resolve individually.                                                                                                       | A typo no longer falsely implies the backup is gone.                                                                                                                   |
| An unknown write advanced the revision but retained the previous write as its source. | The coordinator records the failing tool as an uncertain last write whenever its outcome may have changed the workbook.                                                                                                                                                              | Stale-write errors now identify the uncertain operation while still requiring a reread.                                                                                |
| CSV loses the original distinction between text, number, boolean and formula.         | Added `sheet-to-json` / `json-to-sheet` in the sandbox. For ambiguous text beginning with `=`, a dedicated Office.js read checks whether the cell really has a formula. Typed cell objects reuse the existing overwrite check, approval, chunked commit and formula-error reporting. | Mixed-type data can be round-tripped without converting text dates, IDs or literal `=...` text. Formatting is not included; CSV remains an intentionally untyped path. |
| One task repeatedly searched for already-loaded Office tools and never wrote.         | A `PreToolUse` hook rejects Office-only ToolSearch queries with a direct-call instruction. Deferred COM searches remain available.                                                                                                                                                   | The observed ineffective search path is rejected, but a model can still make other reasoning or execution errors.                                                      |
| Repeated formula failures could continue with slightly changed arguments.             | The tool boundary limits failed formula writes to the same target across argument variations; a reread permits one more cycle, then trial-and-error stops for the turn. Permission and transient errors do not consume this budget.                                                  | The observed formula retry loop is bounded without preventing a corrected next user turn.                                                                              |
| The model could finish immediately after a write without inspecting the target.       | Per-turn write evidence tracks target reads, including completed paginated sandbox exports. A Stop hook requests a read once before finishing if any target remains unread; the task pane and eval observer receive a `task_check` status.                                           | An unchecked write is visible, but a read alone does not prove the task answer.                                                                                        |
| Deterministic bulk edits had no executable expected-result comparison.                | `assert-sheet-json` compares a typed expected matrix, prepared independently from source data, with every cell in the live target range. Mismatches name cells; `task_check` records when all written targets matched an expected matrix.                                            | It proves equality to the supplied matrix, not that the matrix captures every requirement in the user's request.                                                       |
| CSV could silently change cell types when written back over an exported range.        | Within one turn, `csv-to-sheet --force` refuses an overlapping range exported by `sheet-to-csv` unless `--allow-type-loss` is explicit.                                                                                                                                              | Accidental same-turn CSV round trips are blocked; unrelated generated CSV writes still work.                                                                           |

Validation: all 228 Node tests passed; `npm run build:pane` passed. A local mock provider running the installed Agent SDK confirmed the search hook rejects an Office-only search and still permits a deferred tool search and execution. The typed and assertion paths passed both mocked-bridge checks and a live Excel smoke run covering `sheet-to-json`, `json-to-sheet`, `assert-sheet-json`, formula/text distinction, recovery ID errors, and a real Qwen turn's `task_check` result.

Task-level semantic correctness remains a distinct, open capability. The write receipt confirms commit and mechanical read-back. `assert-sheet-json` can verify a deterministic expected matrix when the agent supplies one, but no generic code can infer every task's intended answer from a successful tool call. `read_after_write` is not a semantic pass; even `expected_values_matched` only means the supplied matrix matched. For formula cells, the typed matrix compares the formula text, not its calculated value; the formula result must still be checked separately. A `no_write` status records that the turn made no workbook change, but it cannot infer whether the user asked for one. Only the 48 previously failed tasks were rerun on this version: 13 passed, 28 had answer mismatches, 5 had infrastructure or grading exceptions, and 2 did not complete. The 52 previously passed tasks were not rerun, so this is not a measured improvement to the full 100-task pass rate.
