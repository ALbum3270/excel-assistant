# 任务结果检查：实现依据

## 模块与现有实现

| 模块 | 现有实现 | 本轮接入 |
| --- | --- | --- |
| 工作簿读取 | office-agents 的 `getCellRanges`，本项目已有分页与类型保留补丁 | 复用完整分页读取，不把截断结果当全量 |
| 验证规程 | fabric-rlm 的 `skills/validation.md`：先写验证器，核对长度、唯一性、来源、汇总和边界 | 声明检查条件，读取实际结果执行检查，返回失败位置 |
| 写入确认 | Pi 的 `write-cells.ts`、`mutation/finalize.ts` 及本项目回执 | 保留机械读回状态，独立展示任务约束检查 |
| 生命周期与展示 | 现有 SDK 轮次、工具返回、`turn_complete` 和任务窗格 | 每轮独立检查计划；模型可主动检查，正常结束时再执行一次 |

## 未采用的候选

- fabric-rlm 的 `verified_task` 会执行两次独立求解，源码文档明确仅用于只读任务；不能重复执行工作簿修改。
- Pi 的公式错误检查不能验证输出行数、去重、来源成员关系；不把机械验证当任务语义正确。
- 不分析自然语言来猜测检查条件，也不因检查失败自动撤销或重写；条件由代理根据用户要求显式提供。

## 必要胶水与范围

- 一个只读工具定义和执行检查计划：非空行数、行唯一性、非空单元格、预期值、来源成员、来源行多重集合、公式覆盖、数值合计。
- 来源约束在定义计划时保存输入快照，支持原地排序/筛选后验证。目标数据在检查时重新读取；数值与文本不隐式互换。
- 计划在每轮开始时重置；成功结束时自动执行已有计划。未提供计划、读取失败、检查失败各自报告，均不等于通过。
- 检查通过只证明声明的约束，不证明模型已完整理解任务；任意业务逻辑仍可用现有 Python 沙箱独立计算预期值。
- 读取总量有上限，超限要求缩小范围或使用沙箱。此次检查不提供跨 Office.js/COM 的原子快照；统一协调是下一个 P0。
